# NMEA2000 Integration for rusEFI

This branch adds NMEA2000 marine network protocol support to rusEFI, enabling the ECU to broadcast engine data to onboard boat instruments (chart plotters, engine gauges, multifunction displays) via the NMEA2000 / CAN bus.

Hardware: Proteus F4 board (STM32F4)

## How It Works

The integration adds a new CAN dashboard type `CAN_BUS_NBC_NMEA2K` (enum 13) selectable in TunerStudio. When selected, the `canDashboardNMEA2000()` function in `firmware/controllers/can/can_dash.cpp` handles all NMEA2000 communication.

The NMEA2000 library is lazily initialized on first call. The ECU identifies itself as:
- Product: "rusEFI Eidothea"
- Device function 140 (Engine), class 50 (Propulsion)
- Node address 22, NodeOnly mode
- CAN bus index 1 (extended IDs)

## PGN Transmission Schedule

### Every 100ms
- **PGN 127488** (Engine Parameters, Rapid Update) — RPM and MAP/boost pressure
- **Raw CAN 0x180 / 0x181** on bus 1 — Lambda1 and Lambda2 (uint16, big-endian, scaled /0.0001)
- **PGN 130311** (Outside Environmental) — worst-case (leanest) lambda sent as "atmospheric pressure"

### Every 1000ms
- **PGN 127489** (Engine Parameters, Dynamic) — oil pressure, oil temp, coolant temp, alternator voltage, fuel rate, coolant pressure, fuel pressure, plus 24 diagnostic status flags (see below)
- **PGN 127493** (Transmission Parameters) — intake air temp sent as "transmission oil temp"

### Every 50ms
- `NMEA2000.ParseMessages()` — processes incoming N2K bus traffic

## Sensor Mapping

| NMEA2000 Field | rusEFI Sensor | Notes |
|---|---|---|
| Engine Speed | `Rpm` | |
| Boost Pressure | `Map` | kPa |
| Oil Pressure | `OilPressure` | kPa, x1000 for PGN (Pa) |
| Oil Temperature | `AuxTemp1` | Celsius -> Kelvin |
| Coolant Temperature | `Clt` | Celsius -> Kelvin |
| Alternator Voltage | `BatteryVoltage` | Volts |
| Coolant/Water Pressure | `AuxLinear1` | kPa, x1000 for PGN (Pa) |
| Fuel Pressure | `AuxLinear2` | kPa, x1000 for PGN (Pa) |
| Fuel Rate | `fuelConsumption` | g/s -> l/h (/ 720) |
| Lambda 1 & 2 | `Lambda1`, `Lambda2` | /0.0001 scaling |
| Intake Air Temp | `Iat` | Sent as transmission oil temp |

## Diagnostic Flags (evaluated every 1000ms)

All engine protection flags are only evaluated when RPM > 400 (engine running).

### Emergency Stop — MAP sensor failure
Triggered if battery > 7V AND (MAP == 0 OR MAP >= 101 kPa). MAP of 0 means sensor disconnected; above atmospheric means sensor fault.

### Low System Voltage (5-second debounce)
RPM-dependent thresholds to distinguish charging vs. non-charging states:
- Engine off (RPM <= 400): 11.7V
- Idle (RPM > 400): 12.5V
- Running (RPM >= 750): 13.0V

Debounced for 5 seconds to tolerate transient loads from trim pump and anchor winch.

### Overtemperature
Oil temp (AuxTemp1) > 125C OR coolant (Clt) > 77C.

### Low Fuel Pressure (MAP-compensated)
Threshold: 275 kPa - (100 - MAP). Normal full-load fuel pressure is 285 kPa; 0.1 bar margin, adjusted for manifold vacuum.

### Low Water Flow
Measured via AuxLinear1 (water pressure sensor):
- RPM < 1000: threshold 15 kPa
- RPM >= 1000: threshold 25 kPa

### Low Oil Pressure (RPM-based lookup)
Thresholds derived from measured log data with ~50 kPa safety margin:

| RPM | Threshold (kPa) | Measured Minimum (kPa) |
|---|---|---|
| < 750 (idle) | 150 | 180 |
| >= 750 | 190 | 240 |
| >= 1400 | 275 | 327 |
| >= 2250 | 325 | 375 |

### Critical Error Action
On overtemp, low oil pressure, or low fuel pressure: `setError()` is called with OBD code 1 (triggers audible alarm/beeper). `flagWarning1` reflects `engine->engineState.warnings.isWarningNow()`.

## Submodules

### firmware/controllers/can/NMEA2000
Fork of [ttlappalainen/NMEA2000](https://github.com/ttlappalainen/NMEA2000) at https://github.com/tobsec/NMEA2000 (branch: `rusefi`).

Single change: unconditionally defines `N2K_NO_GROUP_FUNCTION_SUPPORT` in `src/NMEA2000_CompilerDefns.h` to avoid a hard fault in `tN2kGroupFunctionHandler` constructor (setting `pNext=0` crashes on this target).

### firmware/controllers/can/NMEA2000_rusefi
Custom CAN driver adapter at https://github.com/tobsec/NMEA2000_rusefi (branch: `rusefi`).

- Class `tNMEA2000_esp32` (name kept to avoid patching NMEA2000 lib include paths)
- `CANSendFrame()` wraps rusEFI `CanTxMessage` with extended IDs on bus index 1
- `CANGetFrame()` is a stub — receive not yet implemented
- `millis()` bridges to ChibiOS `chVTGetSystemTime()` / `TIME_I2MS()`
- Custom 8KB bump allocator overriding `operator new`; `free()` calls `NVIC_SystemReset()`

### firmware/libfirmware
Fork at https://github.com/tobsec/libfirmware (branch: `NMEA2000`).

- Adds `-lstdc++` to linker flags (required by NMEA2000 C++ library)
- Adds `-Wno-alloc-size-larger-than` to suppress GCC warnings

## Other Firmware Modifications

- **efifeatures.h**: `LUA_USER_HEAP` reduced 25000 -> 20000 to free RAM
- **can_hw.cpp**: CAN RX thread stack size factored into `CAN_THREAD_STACK_SIZE` macro
- **can_msg_tx.cpp**: transmit timeout reduced 100ms -> 10ms; added null assertion; renamed to `canTransmitTimeout` for debugger visibility
- **can_dash.cpp**: `#if EFI_CAN_SUPPORT` guard commented out (file always compiled)
- **rusefi_enums.h**: Added `CAN_BUS_NBC_NMEA2K = 13`

## Not Yet Implemented

- Receiving/parsing incoming NMEA2000 messages (CANGetFrame is a stub)
- Engine hours tracking (hardcoded 0.0)
- TPS/pedal sensor validation flags
- checkEngine flag (commented out — root cause not directly visible on instrument)
- Scheduler-based N2K message timing (using rusEFI CanCycle intervals instead)
